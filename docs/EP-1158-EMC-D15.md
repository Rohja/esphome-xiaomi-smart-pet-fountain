# Board `EP-1158-EMC-D15` (XWWF01MG-EU)

Fully local firmware for the newer board revision found in the EU fountain `XWWF01MG-EU`.
It is **not** the same hardware as `EP-1158-3C-D11`: there is no water level photoresistor, the water
level and the pump state are sensed **through the pump line itself** (GPIO13), and the LED colours differ.

- Package: [`esphome/EP-1158-EMC-D15.yaml`](../esphome/EP-1158-EMC-D15.yaml)
- C++ helper (external component): [`components/xiaomi_fountain_d15`](../components/xiaomi_fountain_d15)

Tested on one fountain for several days, with real lid / empty tank / blocked pump tests.

:warning: **Make sure your pet has another source of water while you test.**

## Hardware

ESP-WROOM-02D (ESP8266, 2 MB flash).

| Pin    | Usage                                            | Notes                                   |
| ------ | ------------------------------------------------ | --------------------------------------- |
| GPIO13 | Pump control **and** pump/water sensing          | Output inverted (0 = pump on); read as an input between pulses |
| GPIO4  | Left LED common + (Normal mode)                  | Active high                             |
| GPIO5  | Right LED common + (Smart mode)                  | Active high                             |
| GPIO14 | LED colour channel: white                        | Active low                              |
| GPIO15 | LED colour channel: violet                       | Active low                              |
| GPIO16 | LED colour channel: cold white                   | Active low                              |
| GPIO3  | Central red "problem" LED                        | Inverted (0 = on). UART RX pad          |
| GPIO1  | Front button (mode)                              | Inverted, pull-up. UART TX pad          |
| GPIO0  | Bottom button                                    | Inverted, pull-up. Also the boot / download-mode button |

Because GPIO1 / GPIO3 are used, serial logging is disabled (`logger: baud_rate: 0`): read the logs over
Wi-Fi (`esphome logs`).

### Flashing

1. Solder wires on the `TX` / `RX` / `GND` / `3.3V` pads.
2. Hold the bottom button (GPIO0 to GND) while powering the board to enter download mode.
3. **Back up the stock firmware first** (2 MB):
   `esptool.py --baud 115200 read-flash 0x0 0x200000 stock-EP-1158-EMC-D15.bin`
   (restore later with `esptool.py write-flash 0x0 stock-EP-1158-EMC-D15.bin`).
4. Flash the ESPHome binary the same way; next updates go over the air.

## How the water / pump sensing works

This is the logic of the stock firmware, reproduced and checked against real measurements:

- The pump is driven in a loop: **1 s on, then GPIO13 is released and sampled every 10 ms for 0.5 s**.
- In each 0.5 s window the falling edges are counted (the last level is kept across windows):

| Falling edges | Meaning      | Confirmed after |
| ------------- | ------------ | --------------- |
| 0             | Water OK     | 3 windows       |
| 1             | Lid open (pump unplugged, line stays high) | 3 windows |
| 2             | No water     | 4 windows       |
| 3 to 5        | Pump blocked | 4 windows       |
| ≥ 6           | ignored (counters reset) | -   |

- When a fault is confirmed the pump is **no longer driven**; the line is only watched, and the state is
  re-checked with normal cycles from time to time: lid open every 10 s (and immediately when the lid is put
  back), no water every 60 s, pump blocked every 60 s (and immediately after the lid is lifted and put back,
  e.g. after cleaning the impeller).
- A pump that was stopped shows spin-up pulses that look like a blockage, so **every restart** (mode change,
  smart mode ON phase, end of a fault, re-check) uses a 3 s first pulse and ignores the first 3 windows.

## Features

- **Mode** select: `Normal` (pump always on), `Smart` (stock schedule: 10 min on / 10 min off by day,
  10 min on / 50 min off by night; day hours set by `day_start_hour` / `day_end_hour`), `Off`.
  Normal → Smart starts with the pause; Off → Normal / Smart restarts the pump and re-measures.
- **Status** text sensor, the single place to look: `Off`, `Checking`, `Running`, `Paused (smart mode)`,
  `No water`, `Pump blocked`, `Lid open`.
- **LED mode** select for the mode LEDs: `On`, `Off`, `Timed` (go out after `led_timeout_s`).
  The central red LED blinks whenever there is a problem, whatever the LED mode.
- **Filter remaining** / **Cleaning due in** (hours, device class `duration`: pick "days" as display unit
  in Home Assistant), with **Reset filter** / **Reset cleaning** buttons. Limits from the stock firmware:
  filter 720 h (30 days), cleaning 168 h (7 days). Counted while the mode is not Off, saved in flash.
- Buttons:
  - front: short press Normal ↔ Smart (Off → Normal), hold 2-6 s Off ↔ Normal;
  - bottom: short press cycles the LED mode, hold 1.5-4 s LED colour test, hold ≥ 5 s resets both counters.
- Works without Wi-Fi / Home Assistant (the day/night schedule assumes "day" until the time is synced).

## Installation

```yaml
packages:
  xiaomi_fountain:
    url: https://github.com/Rohja/esphome-xiaomi-smart-pet-fountain
    ref: master
    files: [esphome/EP-1158-EMC-D15.yaml]
    refresh: 1d

substitutions:
  name: "pet-fountain"
  friendly_name: "Pet Fountain"
  timezone: "Europe/Paris"
  # log_level: "DEBUG"   # one log line per sensing window, useful to tune / report issues

api:
  encryption:
    key: !secret api_encryption_key

ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: ${name}
    password: !secret ap_password

captive_portal:
```

To carry over a partially used filter, override the counters (minutes already used):

```yaml
globals:
  - id: !extend filter_used_min
    initial_value: '37320'   # 622 h
```

## Tuning

All timings are public members of `xiaomi_fountain_d15::ctl` and can be changed from an `on_boot` lambda
(e.g. `xiaomi_fountain_d15::ctl.warmup_windows = 4;`). If your board shows swapped left / right LEDs or
other colours, flip `LEFT_IS_PIN4` / `LED_COLOR_ACTIVE_LOW` or use the colour test (bottom button held
1.5-4 s, the mask is logged).
